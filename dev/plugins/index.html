Country plugins

Everything that depends on the data of a country lives in a plugin: a singleton subtype of AbstractCountry adding methods to a small set of interface functions. The public API (download_data, process_data, estimate_growth, create_report) only talks to plugins through this interface, and takes care of caching, aggregation to regions and country, subregion and species matching, growth models and reports.

The France plugin is the submodule ForestDataExplorer.France (src/countries/France/). Its data sources are configured in sources.toml, so URLs can be updated without touching the code.

Adding a country

  1. Create src/countries/<Country>/<Country>.jl with a submodule defining struct Plugin <: AbstractCountry end.
  2. Implement the interface methods listed in the docstring of AbstractCountry: country_name, download!, admin_units, process, growth_observations, plot_observations, boundaries, forest_cover and data_sources. process must return additive totals at the department (second administrative) level with the columns year, region_code, region, department_code, department, specie, vol, ha, harvested_volumes, mortality_volumes, biological_growth, n_plots.
  3. Include the file in src/ForestDataExplorer.jl and register the plugin in __init__ with register_country!(<Country>.Plugin()).

In a future version plugins may become package extensions, loaded when the user installs a country-specific package; the interface would stay the same.

ForestDataExplorer.AbstractCountry — Type
abstract type AbstractCountry

Supertype of the country plugins.

A plugin P <: AbstractCountry must implement the following methods (dir is the cache folder returned by data_dir):

MethodReturns
country_name(::P)the display name of the country, e.g. "France"
download!(::P, dir; force)nothing; downloads raw inventory, borders and land cover into dir
admin_units(::P)DataFrame with columns region_code, region, department_code, department
process(::P, dir; window)department-level DataFrame of totals (see process_data)
growth_observations(::P, dir)DataFrame with columns region, department, specie, age, volume, diameter, height
plot_observations(::P, dir)DataFrame with columns year, x, y, region, department, vol_ha (map CRS)
boundaries(::P, dir, level)Vector{AdminShape} for level in (:country, :region, :department)
forest_cover(::P, dir)DataFrame with columns department_code, broadleaved, coniferous, mixed, land_area (ha)
data_sources(::P)Vector{String} of citations to print in reports

Plugins are made available by name with register_country!.

ForestDataExplorer.France — Module
ForestDataExplorer.France

Country plugin for metropolitan France.

Data sources (URLs in sources.toml, next to this file):

  • Forest inventory: IGN raw data of the annual campaigns (2005 onwards): plots (PLACETTE.csv), trees (ARBRE.csv) and the species code list (espar-cdref13.csv);
  • Land cover: Corine Land Cover 2006 forest classes 311 (broadleaved), 312 (coniferous) and 313 (mixed);
  • Administrative borders: simplified GeoJSON of the country, its 13 regions and 96 departments.

See the "Methodology" page of the documentation for how indicators are estimated.
